# CLAUDE.md

Guidance for Claude Code (and other AI agents) working in this repo.

## Project

greenlint is a single-module Python CLI (`greenlint.py`) that statically
analyses source and config files for **energy-wasteful patterns** (busy loops,
sub-100ms polling, every-minute crons, `SELECT *`, full-history CI clones,
etc.). Rules are regex + context based and language-tagged; the rule set *is*
the product. Entry point: `greenlint:main` (installed as the `greenlint`
command). Tests live in `tests/`.

## Commands

```sh
make dev     # editable install with dev deps (pytest, ruff, build)
make lint    # ruff check .
make test    # pytest -q
make build   # python -m build
```

## Conventions

- Match existing style; don't reformat unrelated code.
- Conventional Commits for messages (see CONTRIBUTING.md) — they drive the
  release-please version bump.
- `CHANGELOG.md` is generated by release-please; don't edit it by hand.
- Update `docs/` and `examples/` with behavior changes.
- Never commit secrets; CI runs gitleaks. Keep `.env` out of git.

## Guardrails

- Keep greenlint dependency-free at runtime; prefer stdlib.
- New rules need an energy rationale (the `suggestion` field) and a test.
- Don't touch generated files or lockfiles by hand.
- Ask before large refactors or destructive operations.
